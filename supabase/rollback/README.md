# سياسة التراجع عن ترحيلات Supabase

يجب أن يملك كل ترحيل جديد ملفًا مقابلًا بالاسم نفسه داخل هذا المجلد. لا يُسمح باستثناء جديد إلا إذا كان مسجلًا في `irreversible.json` مع سبب واضح وخطة استعادة من نسخة احتياطية.

## تصنيف الترحيلات

- `rollback`: ملف SQL قابل للتنفيذ يعيد بنية الترحيل أو يوقف أثره المستقبلي. يجب التنبيه إذا كانت الصفوف المحذوفة لا يمكن استعادتها.
- `irreversible`: لا يمكن عكسه بأمان، مثل حذف بيانات سبق حذفها أو تغييرات تاريخية لا يمكن إعادة بنائها. هذا التصنيف لا يعني أن البيانات محمية؛ يجب أخذ نسخة احتياطية قبل التطبيق.

## قواعد التشغيل

1. لا يُنفذ ترحيل يمس بيانات أو صلاحيات قبل أخذ نسخة احتياطية موثقة.
2. لا يُعدّل ترحيل مطبق؛ الإصلاح يكون بترحيل جديد.
3. لا يُسمح بإضافة ملف إلى `irreversible.json` من دون `reason` و`backupRequired: true`.
4. يفشل فحص CI إذا وُجد ترحيل بلا rollback أو استثناء موثق، أو وُجد استثناء لملف لم يعد موجودًا.
5. ملفات rollback توثيقية ولا تعيد الصفوف المحذوفة ما لم تنص صراحة على ذلك.

شغّل الفحص محليًا عبر:

```bash
npm run check:migrations
```
