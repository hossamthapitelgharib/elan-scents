# اختبار قاعدة بيانات نشاط العملاء — 14 أكتوبر 2026

**النتيجة:** نجح تنفيذ اختبار Supabase المعاملي دون أخطاء.

**التغطية:** سجل الاختبار في [`tests/customer-activity-transactional.test.sql`](../../tests/customer-activity-transactional.test.sql) أنشأ داخل معاملة بيانات اصطناعية لزائر وعميل مسجل، وتحقق من إنشاء profile محلي، وسلة الزائر، وسلة العميل المسجل، والجلسات المنفصلة، وأحداث `view` و`search` و`cart_add` و`cart_remove`، والـviews المنفصلة، ولقطات المنتج في الأحداث والسلال.

**سلامة البيانات:** استخدم الاختبار استثناءً داخليًا مقصودًا لإرجاع كل writes، ثم تحقق من عدم وجود صفوف العميل/الـprofile/الزائر/الجلسات/الأحداث/التحليلات/السلة الاصطناعية، ثم نفّذ `ROLLBACK` خارجيًا. كانت نتيجة استدعاء الاستعلام `[]` دون خطأ؛ لم تُقرأ أو تُعدّل بيانات أشخاص حقيقيين، ولم يُستدعَ Auth API أو بريد إلكتروني.

**حدود التشغيل:** هذا اختبار تكامل يدوي في هذه الجولة. لا يشغّله GitHub Actions تلقائيًا لأنه لا يوجد مشروع/فرع Supabase مخصص للاختبار وسر CI معتمد؛ لا يُستخدم مشروع الإنتاج لخطوات CI متكررة. عند push التالي سيرفع Workflow ملف التقرير ضمن `reports/test-runs/` كجزء من الـArtifact.
