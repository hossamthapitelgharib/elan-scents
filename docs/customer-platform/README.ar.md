# مشروع لوحات العملاء وبيانات المتاجر

هذا مجلد العمل المرجعي للمشروع الذي طلبه مالك Élan Scents. **يبقى نص التكليف الأصلي هو المرجع الحاكم**؛ لا يُوسَّع أو يُختصر تفسيره بصمت.

## الوثائق

- [نص التكليف الحاكم](./requirements.ar.md) — نسخة محفوظة من رسالة المالك.
- [تدقيق الحالة وخطة التنفيذ](./audit-and-roadmap.ar.md) — ما هو منفّذ، وما يحتاج تحسينًا، والفجوات، وخطوات المتابعة.
- [جاهزية الإطلاق](./launch-readiness.ar.md) — الحالة الحية المتحقق منها، وما يلزم المالك قبل الإطلاق، والتحسينات المؤجلة.
- [خريطة الملفات ومسارات التشغيل](./file-map.ar.md) — فصل الصفحات والـAPI وقواعد عدم كسر المسارات الحالية.
- [جرد قاعدة المتاجر](./store-schema-inventory.ar.md) — الجداول والحقول والعلاقات الفعلية ولوحات الإدارة والفجوات.
- [اختبار قاعدة البيانات المعاملي](./database-fixture-validation.ar.md) — تنفيذ حقيقي ببيانات اصطناعية متراجعة والتحقق من عدم بقائها.
- [تقرير سجل عمليات البحث](../../reports/test-runs/2026-10-15-customer-search-operations.md) — تنفيذ نص الاستعلام ونتائجه للزائر والعميل واختبار الصلاحيات والنقل عند التسجيل.
- [مراجعة بصمة الزائر](./visitor-identity-review.ar.md) — الحالة الفعلية، قيود المطابقة، بيانات Supabase الحية، ومقترحات الدقة والأداء.
- [تسوية تاريخ الترحيلات](./migration-history-reconciliation.ar.md) — الأدلة الخاصة بمصدري الترحيلين التاريخيين غير المتاحين.
- [إغلاق مرحلة العميل](./customer-phase-closure.ar.md) — ما أُنجز وكيف تحققنا وما يلزم المالك وما أُجّل، قبل الانتقال إلى مرحلة المتاجر.
- [إغلاق مرحلة المتاجر](./store-phase-closure.ar.md) — تحصين قاعدة المتاجر، ربط حسابات أصحاب المتاجر من لوحة الإدارة، تحسينات لوحة المتجر، وما أُجّل لقرار المالك، قبل الانتقال إلى مرحلة المنصة.
- [إغلاق مرحلة المنصة](./platform-phase-closure.ar.md) — سجل عمليات المنصة، لوحة المنصة بأقسام مستقلة، فلاتر الطلبات من الخادم، وتوحيد معنى «تحتاج مراجعة»، وما يلزم المالك وما أُجّل.

## خطوط الفصل غير القابلة للخلط

1. **طلباتي (`account.html`)**: مساحة العميل المسجل لطلباته وسلته وبيانات حسابه المسموح بها. ليست لوحة إدارة العملاء.
2. **لوحة العملاء (`customers-dashboard.html`)**: للإدارة المخوّلة فقط؛ تفصل الزوار عن العملاء المسجلين، وتعرض بيانات النشاط والتحليلات الإدارية.
3. **لوحة المتاجر (`stores-dashboard.html`)**: للإدارة، وتدير معلومات المتاجر وعروضها وطلباتها وما يحدده نطاق المتجر.
4. **لوحة إدارة المنصة (`platform-dashboard.html`)**: للإدارة، وتعرض ملخص المنصة؛ لا تُستعمل لعرض السجلات الفردية إلا عبر لوحة العملاء وصلاحية إدارية محددة.
5. **قاعدة Supabase**: مصدر البيانات والجداول والعلاقات؛ لا يمنح وجود سجل في قاعدة البيانات العميلَ حق قراءته. الوصول عبر واجهات الخادم المحمية وسياسات RLS.

## طريقة العمل

- لا تُنقل ملفات التطبيق أو تُغيّر مسارات URL دفعة واحدة. يعتمد الخادم على مسارات حالية كثيرة، لذلك يكون تنظيم الشيفرة تدريجيًا مع اختبارات توافق.
- تغييرات قاعدة البيانات تُضاف كترحيلات متتابعة، وتُطابق أرقامها مع سجل Supabase الفعلي.
- كل تغيير في التقاط نشاط العميل أو عرضه يختبر الدورين (زائر/مسجل) واختبارًا منفصلًا يمنع العميل العادي من قراءة بيانات الإدارة.
- تظل المتطلبات المستقبلية غير المذكورة في النص الأصلي «معلّقة بانتظار تحديد المالك» بدل افتراضها.
