# تحصين الخطة المجانية — 2026-11-02

هذا الملف يحدد ما يمكن تحسينه داخل المستودع دون إضافة خدمة مدفوعة أو تغيير خطة Cloudflare/Supabase.

## ما تم تطبيقه

- **عزل بيئة Worker:** `cloudflare/worker-core.js` يتتبع القيم التي كتبها adapter إلى `process.env` ويمسح القيمة التي لا تأتي في الطلب التالي. هذا يمنع بقاء إعداد أو سر اختياري من طلب سابق داخل طلب لاحق.
- **اختبار العزل:** اختبار Worker يغطي binding موجودًا ثم غيابه في الطلب التالي.
- **حدود المعدل:** مسارات `createDistributedLimiter` تستخدم الآن RPC ذرية مشتركة في Supabase مع HMAC للمعرّف وعدم تخزين عنوان IP الخام؛ `STATE_STORE_REQUIRED=1` يجعل غياب المخزن فشلًا مغلقًا بدل الحد المحلي. لا توجد خدمة جديدة أو تكلفة Worker إضافية؛ كل فحص موزع هو طلب REST واحد يستهلك حصة Supabase، وتُراقَب حدودها.
- **إعدادات Worker:** صار `GITHUB_TOKEN` و`SUPABASE_SERVICE_ROLE_KEY` من نوع Secret في إعدادات Worker الحية، وفُعّل `redact_query_string` للسجلات.
- **اختبارات التدفقات:** توجد اختبارات Chromium محلية، واختبارات Worker، واختبارات live مخصصة في GitHub Actions. تشغيلها لا يحتاج خدمة مدفوعة، لكن اختبارات البريد الحقيقي والتخزين الحقيقي تحتاج حسابات الإنتاج نفسها.
- **الكاش والإصدارات:** `asset-manifest.json` و`bump-asset-version.js` واختبار immutable يحمون من تعديل ملف ثابت دون تغيير نسخته.
- **التطابق بين Node وCloudflare:** اختبارات `cloudflare-build` و`cloudflare-worker` تقارن الملفات العامة وسلوك Worker بخادم Railway المحلي.
- **الأصول القديمة:** `assets/hero.mp4` و`assets/hero-poster.jpg` محتفظ بهما عمدًا كأصول توافق واختبار Range/Media؛ لا يجوز حذفهما دون تعديل اختبارات الفيديو ومسار التوافق.

## ما لا يمكن حسمه من الكود وحده

- كشف كلمات المرور المسرّبة المدمج في Supabase Auth يتطلب خطة Pro أو أعلى، بينما المؤسسة حاليًا على الخطة المجانية؛ لم تُرقَّ الخطة ولم يُعطّل تسجيل الدخول. يجب قرار المالك بين الترقية أو سياسة أخرى تحفظ خصوصية العميل.
- تدوير `GITHUB_TOKEN` و`SUPABASE_SERVICE_ROLE_KEY` ما زال لازمًا لأن تغيير binding من `plain_text` إلى `secret_text` لا يغيّر قيمة المفتاح نفسها.
- التحقق من البريد، رابط إعادة كلمة المرور، رفع فيديو حقيقي، وحفظ المحرر ثم نشره تحتاج تجربة على حسابات الإنتاج.
- حفظ المحرر على `main` قرار تشغيل مقصود. الاختبارات تمنع التعارض وتنتظر تأكيد النشر، لكنها لا تنشئ staging مدفوعًا.
- تدوير أسرار Worker وإدارة صلاحيات GitHub يجب أن يتم من لوحات Cloudflare/GitHub، وليس بتخزين الأسرار في Git.

## تشغيل مجاني موصى به

1. شغّل `npm ci --no-audit --no-fund` ثم `npm test` و`npm run test:browser` قبل أي نشر.
2. شغّل فحوص `live-check` و`live-open-check` يدويًا بعد النشر الناجح.
3. راقب GitHub Actions بدل إضافة خدمة مراقبة خارجية.
4. أبقِ صلاحية GitHub للمحرر مقتصرة على مستودع `elan-scents` وContents Read/Write فقط.
5. عند ظهور ضغط حقيقي، استخدم قواعد Cloudflare المجانية أو WAF المتاح في الحساب قبل رفع حدود التطبيق.
6. لا تعتبر نجاح الاختبارات المحلية دليلًا على وصول البريد أو نجاح Storage الحقيقي؛ نفّذ قائمة التحقق الحية الموثقة في `docs/handoff.ar.md`.
